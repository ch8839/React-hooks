# gen-locale

这是一个专门用于前端工程（React/antd）的多语言文案自动化维护工具。它通过解析 CSV 文件，精确地在现有语言包中追加新 Key 或更新旧文案。

## When to Use

- **新增功能文案**：使用 `/gen-locale create` 将运营新定义的 Key 和文案批量加入项目。
- **文案线上纠错/优化**：使用 `/gen-locale modify` 针对已有 Key 进行多语言内容的批量更新。
- **多版本迭代**：当运营提供的 Excel 包含“新/旧”文案对照或仅包含部分变更项时。

## Instructions

### 1. 环境上下文识别
- **路径探测**：自动定位项目中的多语言文件夹（如 `src/locales`），识别文件后缀（`.json`, `.ts`, `.js`）。
- **结构分析**：分析现有文件是嵌套对象（Nested）还是扁平键值对（Flat），生成时必须严格保持一致。
- **语言匹配**：将 CSV 的列头（如 `en_US`, `zh_CN`）与项目文件名（如 `en.json`, `zh-CN.json`）进行智能模糊匹配。

### 2. 操作指令逻辑

#### [ADD NEW KEYS] `/gen-locale create: @file.csv`
- **核心逻辑**：增量添加。只处理项目中**不存在**的 Key。
- **执行动作**：读取 CSV，如果第一列的 Key 在当前 locales 文件中找不到，则将其及其对应的多语言文案追加到文件中。
- **保护机制**：如果 Key 已存在，跳过该行，不覆盖原有内容。

#### [UPDATE VALUES] `/gen-locale modify: @file.csv`
- **核心逻辑**：内容覆盖。只处理项目中**已存在**的 Key。
- **执行动作**：读取 CSV，如果第一列的 Key 在当前 locales 文件中已存在，则用 CSV 中的新文案替换旧文案。
- **保护机制**：如果 CSV 中的 Key 在项目中找不到，提示用户或忽略，严禁创建新 Key。
- **版本比对**：若 CSV 包含“原回复”和“新回复”列，需校验“原回复”是否与代码中一致，不一致时需询问用户。

### 3. 代码质量要求
- **禁止删除**：无论执行哪种指令，严禁删除项目中已有的、但未在 CSV 中出现的文案。
- **排序规范**：新插入的 Key 应保持项目原有的排序逻辑（通常为字母序或追加到模块末尾）。
- **格式保持**：严格遵守项目的缩进（2/4空格）、引号风格、末尾逗号规范。
- **TS 支持**：如果项目使用 TypeScript 定义多语言类型，需同步更新类型定义。

### 4. 交互流
- 在应用修改前，使用 `ask questions` 工具或在预览中明确告知用户：
  - “检测到 X 个新 Key 将被添加到 [路径]”
  - “检测到 Y 个已有 Key 的文案将被修改”
