# gen-locale

该 Skill 用于将用户提供的 CSV 多语言文案，自动转换为项目中的 i18n 文件内容，支持增量新增和定向修改。

## When to Use

- **新增多语言文案**：使用 `/gen-locale add` 将新定义的 Key 和文案批量加入项目。
- **修改多语言文案**：使用 `/gen-locale modify` 针对已有 Key 进行多语言内容的批量更新。
- **适配多种结构**：无论项目是 JSON、TS 单文件还是多文件结构，均可自动适配。

## Instructions

### Step 1：解析 CSV 规则

根据用户提供的指令（add 或 modify），采用不同的解析策略：

#### [ADD 模式] —— 用于新增 Key `/gen-locale add: @file.csv`
- **识别规则**：
  - 第一列：i18n Key（如 `login_title`）。
  - 后续列：各语言内容（如 `简中`, `en_US`, `fr_FR`）。
- **处理逻辑**：
  - 自动忽略描述、截图、备注等非语言列。
  - **增量操作**：仅处理项目中不存在的 Key，若 Key 已存在则跳过，严禁删除存量文案。

#### [MODIFY 模式] —— 用于修改已有文案 `/gen-locale modify: @file.csv`
- **识别规则**：
  - 第一列：i18n Key（对应项目中的键名）。
  - 第二列：语言标识（标题通常为 `language` 或 `语言`，内容为 `en_US` 等）。
  - 后续列：重点读取  `old` 或 `旧文本`、`new` 或 `新文本`列的内容，用 CSV 中的新文案替换旧文案。
- **处理逻辑**：
  - **定向覆盖**：根据“语言标识”定位到对应的文件或变量，仅修改指定的 Key 对应的 Value。
  - **安全校验**：若 Key 在项目中不存在，需通过 `ask questions` 工具询问用户是否需要改为新增。

---

### Step 2：自动识别项目多语言结构

不要假设固定结构，必须扫描代码库并基于以下常见模式推断：

- **模式 A（多文件 TS/JS）**：`locales/zh-CN.ts`, `locales/en-US.ts`。
- **模式 B（JSON 文件）**：`locales/zh-CN.json`, `locales/en-US.json`。
- **模式 C（单文件多变量）**：在一个文件中 `export const zhCN = { ... }`, `export const enUS = { ... }`。
- **模式 D（嵌套结构）**：对象中存在多级嵌套，如 `login: { title: "..." }`。

---

### Step 3：代码写入规范

1. **结构对齐**：生成的内容必须与已有代码的层级、排序逻辑保持一致。
2. **格式保持**：严格遵守项目的缩进（2/4空格）、引号风格（单/双引）、末尾逗号规范。
3. **语言映射**：自动映射 CSV 语种标识与代码变量/文件名（例如：`en_US` 映射为 `enUS` 变量或 `en-US.ts` 文件）。
4. **类型安全**：如果项目包含 i18n 的 TypeScript 类型定义，需同步建议更新。

## Best Practices

- 在执行修改前，在预览中明确告知用户：
  - “检测到 X 个新 Key 将被添加到 [路径]”
  - “检测到 Y 个已有 Key 的文案将被修改”
- 如果 CSV 结构模糊，务必使用 `ask questions` 与用户确认。
